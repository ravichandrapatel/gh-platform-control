# Workload repositories

Only **dev** and **prod** for MVP — one GitOps repo per AWS account.

| Env | Example repo | AWS | Starter tree |
| --- | --- | --- | --- |
| dev | `OWNER/infra-dev` | dev account | [`examples/infra-dev/`](../examples/infra-dev/) |
| prod | `OWNER/infra-prod` | prod account | [`examples/infra-prod/`](../examples/infra-prod/) |

Register each row in [`config/environments.yaml`](../config/environments.yaml).

## Responsibilities

- Own `stacks/**` OpenTofu roots (usually generated by control IssueOps).
- Call pinned `tofu-pipeline` for plan/apply (stages: validate → plan+OPA → apply).
- Store `MODULES_GIT_TOKEN` (contents:read on `gh-platform-modules`) and pass it as
  `secrets.modules_git_token` so private git modules download during `tofu init`.
- Hold OIDC trust to **that** account’s deploy role.
- Protect `main`; require PR reviews + status checks (prod: Environment reviewers).


## Customization later

Add more envs or split by team/product via new workload repos and registry rows —
keep a **single** control plane.
